Why

Nobody publishes a European-egress, 5-minute-resolution view of MiMo with fixed, disclosed workloads. Artificial Analysis probes from us-central1-a every three hours. llmgateway.io measures passively from real gateway traffic, so its latency mixes whatever prompts its users happened to send at arbitrary cache-hit rates — fine for “is it up”, useless for “is it slower than last week”, and structurally unable to isolate network from inference.

llmstats is a small Go daemon on an OVH server in Roubaix that runs one aligned probe cycle every five minutes and serves a public read-only React dashboard. Backend shape, build and deploy come from ../peeq; the UI stack and visual language come from ../music; the MiMo client comes from ../loom.

The published number nobody else has

TTFT 1 400 ms = 165 ms to the edge + 1 235 ms beyond it

Roubaix→Singapore is ~165 ms of pure transport, so a raw TTFT is mostly wire and means little alone. Measuring the first hop independently in the same cycle makes the remainder directly observable rather than guessed at.

Call the residual “server-side time”, never “model time”

The TCP handshake terminates at the TLS edge. Xiaomi runs no European GPUs, so whatever backhaul exists between that edge and the actual compute sits inside the residual, along with queueing, prefill and scheduling. Calling it “model time” would be a claim the measurement cannot support. The methodology page says so plainly.

The three probes

1 · ping — pure network, free

net.DialTimeout("tcp", host+":443"), measured to TCP handshake completion (SYN → SYN-ACK). No TLS, no HTTP, no auth, no tokens. Records dns_ms, connect_ms, and whether the socket opened.

TargetWhat it answers≈ RTT
token-plan-sgp.xiaomimimo.comis MiMo's edge reachable165 ms
reference · Singapore — an OVH SGP endpoint (ap-southeast-sgp)is any Roubaix→Singapore path healthy~160 ms
reference · Europe — a public anycast address answering from a nearby PoPis our uplink up at all~9 ms

Neither reference is localhost

A machine pinging itself proves nothing about its uplink. Both are public hosts on the open internet — one in the same city as MiMo's edge, one a few milliseconds away.

TCP, never ICMP

ICMP echo is dropped or deprioritised by routers as routine policy, so a timeout would carry no information. It also needs CAP_NET_RAW, which forces a privileged container. A TCP handshake to port 443 traverses the same path, through the same firewalls, as the inference call itself.

2 · infer — one short question, every cycle

~40 input tokens, 2–3 sentences out (~70 tokens, cap 150). Records ttft_ms, ttfat_ms, itl_p50_ms, output_tps, answer_ok, error_class.

What is the capital of France? Answer in two or three sentences.
→ assert the response contains "Paris"

A rotating bank of ~185 factual questions with assertable answers. The rotation buys a correctness canary: a silent reroute to a smaller model shows up as a correctness dip before it shows up as a latency dip — a signal no timing metric can produce. Contested or dual capitals are excluded (Bolivia, South Africa, Israel, Netherlands, Myanmar, Côte d'Ivoire, Eswatini, Sri Lanka, Benin, Tanzania): a wrong-but-defensible answer is worse than no canary. Questions must be near-identical in length, or the rotation injects variance into the very metric being measured.

3 · wide — one large prompt, hourly

~4 000 input tokens, 300 output cap, on every 12th cycle so it always lands on an aligned tick with its own network reading. It exists for two things infer structurally cannot see:

  • Prefill scaling. At 40 tokens prefill is ~zero, so there is no slope and a batching change or requantisation is invisible. 40 → 4 000 is a real gradient.
  • Sustained decode. 300 output tokens is ~7 s of generation, long enough to see throughput degrade mid-stream. At 70 tokens (~1.5 s) only the opening moments are seen.

It also exercises length-dependent failure modes — context errors, rate limits and timeouts a 40-token request would never trigger.

Cache defeat — needed for wide only

infer needs none: nothing caches below ~1 000 tokens. wide is squarely in cacheable territory, and a prefix cache hit skips prefill — silently destroying the one measurement wide exists to take. So it prepends a nonce before the document:

7fK2xQ9m                  ← 8 random base62 chars, kills the first cache block
Summarise the following.
<fixed ~3 000-word document>  ← Darwin, Origin of Species (1859), public domain

Placement is the whole trick: caches key on the leading prefix in sequential blocks, so varying anything after the document leaves the expensive part matching. One document, one framing, only the nonce moves. cached_tokens is recorded every run and must stay near zero.

Fault attribution

The hole llmgateway's client/gateway/upstream split exposed: if our uplink flakes, llmstats would publish provider outages that never happened. On a public site that is credibility-ending. Three network targets make the attribution fall out with no heuristics.

mimo sgpref sgpref euinferVerdict
okokokokFine
okokokfailMiMo's inference is broken — the network is demonstrably fine
failokokfailMiMo's edge is unreachable — the route to Singapore is fine
failfailokfailRoubaix→Singapore route degraded — not MiMo, not us
failfailfailfailOur uplink is down — window excluded from everyone's availability

Disclosed limit, not papered over

The SGP reference proves a path to Singapore is healthy. Green there while MiMo is red narrows the fault to MiMo's specific path or its edge — separating those two would need a traceroute. Same-carrier also means an OVH backbone problem shows in the reference (useful), but a non-OVH segment on MiMo's path would not.

infer starts from loom/backend/internal/llm/client.go + types.go — they already carry the right request shape and target MiMo specifically. loom/…/session.go has the session-id minting to copy verbatim.

That UA claims to be opencode, on a public repo and a public site. The fix is disclosure, not removal: the methodology page prints it verbatim with the reason. Overridable via BACKEND_PROBE_USER_AGENT.

  • net/http/httptrace on every infer run, so each inference sample carries its own DNS/connect/TLS split as a cross-check against the standalone ping.
  • Two first-token timestamps. ttft_ms (first chunk with any delta) and ttfat_ms (first chunk with content). Even with thinking disabled a provider can regress and start emitting reasoning_content; divergence is the alarm.
  • Streaming is not optional. TTFT is unmeasurable without it; it separates “no first token for 170 s” (queueing) from “first token at 800 ms then 2 tok/s” (throughput collapse); and the idle watchdog only exists with chunk arrivals.

Timeouts — layered

A single outer deadline records “slow” and “dead” identically. mimo-v2.5-pro genuinely takes 2–3 minutes when things go bad, so four minutes is the right outer bound — but never the only one.

Port loom's implementation (client.go:59-62 Timeout+IdleTimeout, stream.go:14 ErrStreamStalled). Loom seeds the first idle gap at request start; llmstats wants the TTFT watchdog separated out, because “no first token in 150 s” and “died mid-stream” are different findings.

Three rules that matter more than the numbers

  1. A timeout is a recorded sample, never a dropped one — ok=0, an error_class, and however far it got.
  2. Failed rows are excluded from latency percentiles and counted in availability. Otherwise a 240 000 ms timeout lands in the P50 and an outage reads as catastrophic latency. Gets its own test.
  3. Overrun guard. Per-(model, probe) singleflight: if the previous run is still in flight when the timer fires, skip and increment skipped_runs. Surface the counter — silent skipping makes the availability strip lie by omission.

Schema

The aligned cycle is modelled explicitly, because the network-vs-server subtraction is a join and must not depend on timestamp fuzzing. ~1 200 rows/day, ~110 k over the three-month window. No rollups; percentiles in SQL over a rolling window. Tables are STRICT so a parsing bug cannot silently store text in a REAL column.

cycles(id, started_at, origin)

net_probes(cycle_id, target, dns_ms, connect_ms, ok, error_class)
  -- target: 'mimo_sgp' | 'ref_sgp' | 'ref_eu'

infer_probes(cycle_id, model_id, probe, ttft_ms, ttfat_ms, total_ms,
             -- probe: 'infer' | 'wide'
             itl_p50_ms, itl_p95_ms, output_tps,
             prompt_tokens, output_tokens, cached_tokens, reasoning_tokens,
             question_id, ok, answer_ok, fault, http_status,
             error_class, error_detail)

skipped_runs(occurred_at, origin, model_id, probe)

-- Derived per cycle from the three net_probes rows, stored so the strip and
-- the availability maths agree and the rule is testable in one place:
--   mimo ok                       -> 'ok'
--   mimo fail, ref_sgp ok         -> 'edge'   (MiMo's edge; route is fine)
--   mimo+ref_sgp fail, ref_eu ok  -> 'route'  (Roubaix->Singapore)
--   all three fail                -> 'uplink' (ours; window excluded)
cycle_fault(cycle_id, fault)

error_detail is written for operators and never served publicly — a provider error body can echo request fragments. Public endpoints expose error_class only, and a test asserts it.

GET  /api/methodology
GET  /api/events        -- SSE, pushes each completed cycle

Public and unauthenticated, so:

  • internal/ratelimit — per-IP token bucket on /api/*, plus a hard cap on concurrent SSE subscribers. Without it one scraper pins the server.
  • Response caching — summary/series recomputed once per cycle and served from memory with Cache-Control: public, max-age=30. The DB is never hit per request.
  • Window allow-list: 1h · 24h · 48h · 7d · 30d · 3mo. Nothing longer, because retention deletes at three months and offering a window with no data behind it is a bug. Bucket size is derived server-side (1 h → 5 min, 48 h → 30 min, 3 mo → 6 h) so a caller cannot ask for 100 000 points.
  • Percentile suppression: fewer than 20 successful samples in a window returns insufficient_data, not a number. A P50 from three samples is exactly the figure that gets screenshotted out of context.

Reading the numbers — deviation, not absolutes

“Is 996 ms good?” is unanswerable in the abstract, so no figure is published without the context needed to read it.

  • Higher-is-worse metrics (TTFT, ITL, prefill, edge RTT) are scored against a rolling 7-day median of that same metric. Bands: ≥1.5× elevated, ≥2.5× degraded. Deliberately generous — latency is noisy, and a dashboard that cries wolf at +20 % gets ignored, which is worse than no dashboard. A rolling baseline also keeps working if MiMo gets permanently faster or slower.
  • Lower-is-worse metrics (availability, correctness) are scored against absolute expectations, not a rolling baseline: a model that has been 97 % available all week has not made 97 % acceptable, and a drifting baseline would quietly normalise a fault.
  • “Now” is the last ~30 minutes, not the window median. A 24-hour median hides a problem that started an hour ago — exactly what you most want to see on opening.
  • A verdict banner states it in words, before any number: “mimo-v2.5-pro is having problems right now — availability has dropped to 96.8 % and first tokens are taking 71 % longer than its 7-day normal.” Precedence is uplink → route → edge → model, because each layer makes the ones below it unreadable.
  • Every card carries a state chip (normal / elevated / degraded) and each figure its own delta. Colour is never the only signal.

Chart scale

Latency spans decades: a normal ~900 ms reading and a 90-second queue storm are both real and both must stay legible. A linear axis collapses one of them.

  • The y-axis switches to log automatically when the window's dynamic range exceeds 20×, and shows a log scale badge beside the legend when it does. A log axis read as linear is worse than no chart.
  • Units auto-scale: ms below a second, seconds below a minute, minutes above. Below 100 ms one decimal is kept, because inter-token latency lives there and 11.9 vs 12 is a difference the chart can actually show.
  • Failed runs stay excluded from percentiles; this is about slow-but-successful responses, which must remain in the data.

Verification

  • make test — backend + UI, 75 % coverage floors via hack/coverage-gate.sh.
  • ping correctness: against a local net.Listen that accepts after a known delay, connect_ms must match within tolerance; against a closed port it must record connect_timeout and not panic.
  • infer correctness against httptest fakes emitting SSE at known inter-chunk delays: ttft_ms and itl_p50_ms must come out exactly as constructed. Assert the outgoing request too — UA string, both session headers, thinking.type == "disabled", stream_options.include_usage.
  • Timeout tests, one per layer: never sends headers / headers then nothing / three chunks then silence / dribbles past 240 s.
  • The percentile-exclusion test: a window with one 240 s timeout and nine 900 ms successes must report P50 ≈ 900 ms and availability 90 % — never a P50 dragged toward the timeout.
  • Fault attribution, one case per row of the table: each of the five rows must produce its stated verdict, and the all-fail row must leave every model's availability untouched.
  • Alignment test: every infer_probes row has net_probes rows with the same cycle_id, so the subtraction can never silently fall back to a nearest-neighbour guess.
  • Percentile suppression: 19 samples returns insufficient_data, 20 returns a number.
  • Overrun test: fire the timer mid-run; exactly one run executes and skipped_runs increments.
  • Question bank test: every question within ±10 % token length of the others; no contested-capital country present; every entry has an assertable answer.
  • Retention test: a sample older than the window is swept; one inside survives.
  • Rate limit: N+1 requests inside the window returns 429; the SSE subscriber cap holds.
  • A test asserts no public endpoint ever emits error_detail.
  • Live smoke, once, manually: make run with the real key, one forced cycle, then sqlite3 data/llmstats.db 'select model_id, ttft_ms, itl_p50_ms, reasoning_tokens, answer_ok from infer_probes'. reasoning_tokens == 0 on both models is a hard gate — it proves thinking is actually off.
  • make dev, then open -a Safari http://127.0.0.1:5173 and watch cycles land live over SSE.

Before any code — four curls

  1. Both model IDs are served on the tp- key against token-plan-sgp.xiaomimimo.com. Xiaomi's quick-start page names only mimo-v2.5-pro; the token plan may not carry both.
  2. The output cap is honoured, and under which field name. max_completion_tokens is proven against MiMo (loom sends it in production), but MiMo demonstrably rejects a long list of OpenAI-standard params (reasoning_effort, thinking_budget, seed, logprobs…), so nothing is assumable. Send a low cap, assert finish_reason == "length". An ignored cap blows both the latency numbers and the cost model.
  3. {"thinking":{"type":"disabled"}} is accepted and usage.reasoning_tokens == 0 comes back.
  4. Confirm the reference hosts. Pick and TCP-test the OVH Singapore endpoint and the European anycast address before the attribution logic depends on them.
